# VS Code で Claude と Codex のチャットをショートカットで切り替える

- **記載時点**: 2026-09-11
- **正本**: VS Code のユーザー設定 `keybindings.json`（`%APPDATA%\Code\User\keybindings.json`）。
  このドキュメントは**その時点の記録**であり、設定を変えたらここも古くなる。
- **位置づけ**: 個人の作業環境の記録。**チーム標準ではない。**
- **実機確認**: 2026-09-11。`Ctrl+K` `A` / `Ctrl+K` `X` の打鍵と、`Ctrl+X` の切り取り復帰を実機で確認済み。

## これは何か

VS Code 拡張として Claude Code と Codex（ChatGPT 拡張）を並行して使うとき、
マウスに持ち替えずにチャットへフォーカスを移すためのキー割り当て。

| キー | 移る先 | 語呂 |
| --- | --- | --- |
| `Ctrl+K` → `A` | Claude のチャット | **A**nthropic |
| `Ctrl+K` → `X` | Codex のチャット | code**X** |

2ストロークの chord（`Ctrl+K` を押してから次のキー）として定義している。
**VS Code の既定ショートカットを1つも潰さない**組み合わせを選んである（根拠は後述）。

## 設定内容

`keybindings.json` に次の2件を追加する。

```json
{
    "key": "ctrl+k a",
    "command": "claudeVSCodeSidebarSecondary.focus"
},
{
    "key": "ctrl+k x",
    "command": "chatgpt.sidebarSecondaryView.focus"
}
```

`keybindings.json` は `Ctrl+Shift+P` →「基本設定: キーボード ショートカットを開く (JSON)」で開ける。

反映されない場合は、**ウィンドウの再読み込みではなく全ウィンドウを閉じて VS Code を起動し直す**。

## 拡張の既定ショートカットでは足りない

先に「拡張が持っている既定キーで済むのでは」を確認したが、済まなかった。

| 拡張 | 既定キー | コマンド | 使えない理由 |
| --- | --- | --- | --- |
| Claude | `Ctrl+Esc` | `claude-vscode.focus` / `.blur` | **Windows ではスタートメニューに奪われる**ため到達しない |
| Claude | `Ctrl+Alt+K` | `claude-code.insertAtMentioned` | フォーカスではなく**@メンション挿入** |
| Claude | `Alt+K` | `claude-vscode.insertAtMention` | 同じく挿入系 |
| Claude | `Ctrl+Alt+F` | `claude-vscode.toggleFocusView` | サイドバーが既にアクティブな時だけ有効（`when` 句付き） |
| Codex | — | — | **フォーカス系のキーを1つも持っていない**（既定は `Ctrl+N` = 新規チャットのみ） |

Codex 側は自前で割り当てるしかなく、Claude 側も Windows では既定が実用にならない。

## なぜ `Ctrl+X` を前置キーにしないのか

⚠️ 最初は `Ctrl+X` → `C` / `X` にしていたが、**既定の切り取り（`Ctrl+X`）が動かなくなる**ため変更した。

VS Code では chord の前置キーを押した時点で次のキー入力を待つ。そのため `ctrl+x c` を定義すると
`Ctrl+X` 単独が切り取りに解決されなくなる。**エラーは出ない。**
気づけるのは、右クリックメニューの「切り取り」の表示が `Ctrl+X` から `Shift+Del` に
繰り下がることだけである。

VS Code 本体の既定定義（`editor.action.clipboardCutAction`）:

```js
kbOpts: { primary: 2102, win: { primary: 2102, secondary: [1044] }, weight: 100 }
```

| 値 | 内訳 | 意味 |
| --- | --- | --- |
| `2102` | `2048`(CtrlCmd) + `54`(KeyX) | `Ctrl+X` — 第一候補 |
| `1044` | `1024`(Shift) + `20`(Delete) | `Shift+Delete` — 第二候補 |

切り取りは元々この2つに割り当たっており、第一候補が奪われたぶんメニュー表示が第二候補に落ちていた。

**単独押しと chord 前置は両立しない。** `ctrl+x` を切り取りに再割り当てしても解決しない。

## `Ctrl+K` を選んだ理由

`Ctrl+K` は VS Code が既定から chord の前置キーとして使っているキーで、
**単独押しのコマンドを持たない**。そのため前置キーにしても失われるものがない。

2打目まで含めた衝突は別途確認が必要で、実測した空き状況は次のとおり。

| 前置キー | 2打目で空いている英字 |
| --- | --- |
| `Ctrl+K` | **A B G H J K L Q V X** |

この中から `A`（Anthropic）と `X`（codeX）を採った。

なお `Ctrl+K` → `C` は語呂が良いが、既定の
`workbench.files.action.compareWithClipboard`（アクティブ ファイルをクリップボードと比較）を
上書きするため採らなかった。

## 衝突の調べ方（再現手順）

VS Code 本体のバンドルは chord を `mo(<第1キー>, <第2キー>)` という数値対で持っている。
`Ctrl+K` は `2089`（`2048` CtrlCmd + `41` KeyK）なので、`2089,<2打目>` を全 `.js` から検索すれば
既定の一覧が取れる。拡張側は各 `package.json` の `contributes.keybindings` を見る。

**0件を「衝突なし」の根拠にする前に、陽性対照を1回必ず取る。**
検出できると分かっている対象（例: `2089,2081` = `Ctrl+K Ctrl+C`、拡張側ならキー定義の総件数）で
同じ検索を叩き、1件以上返ることを確認する。
この確認を省いて0件を信じ、**実際は検出方法が壊れていた**という失敗を一度している。

**この調べ方の限界**:

- 「一度も出現しない」＝空き、という判定は信頼できる（どの形式でも言及がないため）
- 一方で「使用中」の判定は**不正確**。`mac:{primary:...}` や、`win:{}` で上書きされる
  mac 専用の定義まで数え込む。**使用中に見えても Windows では空いていることがある**
- キーコードが定数リテラルで並んでいない書き方（実行時計算）は取りこぼす

確実に見たいときは、キーボードショートカット画面（`Ctrl+K` `Ctrl+S`）で当該キーを検索し、
「ユーザー」の行と既定の行が並ぶのを目で確認する。

## コマンドIDについて

どちらも末尾が `Secondary` で、**二次サイドバー（既定では画面右側）に置いたビュー**へフォーカスする。
拡張を一次サイドバー（左側）に置いている場合は別のコマンドIDになるため、そのままでは動かない。

コマンドIDは拡張が決めるもので、**拡張の更新で変わりうる**。効かなくなったときは
キーボードショートカット画面で拡張名を検索し、実際のIDを確認する。

## 未確認事項

- 既定 chord の一覧は VS Code 本体のバンドルから機械抽出した（`Ctrl+K` 前置で105件）。
  **バージョンが変われば変わる**ため、再確認はそのバージョンで行う。
- 検証した環境は Windows / VS Code の1台のみ。他OS・他バージョンでは確認していない。
